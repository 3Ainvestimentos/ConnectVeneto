# O gestor vem da estrutura organizacional

O organograma por "quem reporta a quem" (ADR 0001) não representa como a Vêneto se organiza: uma mesma gestora lidera várias equipes, e várias equipes formam uma área, que fica sob uma diretoria. Decidimos modelar a **estrutura** explicitamente — unidades em árvore Diretoria › Área › Equipe (`orgUnits`), cada uma com um responsável — e fazer o **gestor de cada pessoa vir dela**: quem está numa unidade reporta ao responsável dela; o responsável reporta ao da unidade de cima. Casos fora da regra ficam como **exceção manual** na pessoa (`managerOverrideIdVeneto`). Assim o RH mantém a estrutura, e não o gestor pessoa a pessoa.

O `leaderIdVeneto` do ADR 0001 vira legado: vale só para quem ainda não está numa unidade (ou cuja cadeia não tem responsável). Ordem de resolução: exceção → estrutura → `leaderIdVeneto` → nome em `leader` (único). Quem edita a estrutura é o RH (admin do cadastro de colaboradores) e os super admins, pela tela Pessoas › Estrutura; tudo passa por API com Admin SDK, e `orgUnits` fica fechada ao navegador. Rejeitamos tipos livres sem ordem (fácil de ficar inconsistente) e manter o gestor só por pessoa com a estrutura apenas para agrupar (dobraria o trabalho do RH e as duas visões divergiriam).
